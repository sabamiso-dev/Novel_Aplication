# Novel_Aplication 要件定義書

> 軽量チェックリスト型。Phase 1（MVP）と Phase 2（執筆補助・検索）の機能スコープを固定するための単一ソース。
> Phase 3 は比較項目のみ列挙し決定は保留。

---

## 1. 概要 / Why

クラウド小説執筆アプリ **Nola** の代替を、**月額費用ゼロ・データはすべてローカル保管・サーバー前提機能なし** で自作する。
PWA として 1 コードベースで構築し、自分の PC（主）と自分のスマホ（副）でのみ動かす。

- 想定ユーザー：**作者本人ただ 1 人**。同時利用者は 1 名。
- **完全に個人専用プロジェクト**：第三者への頒布・公開・サービス化は対象外。リポジトリも個人バックアップ用途。
- 重要原則：**外部送信なし／オフライン完全動作／データ可搬性**。
- 一般向けプロダクトに必要な配慮（広範なブラウザ互換、汎用アクセシビリティ準拠、規約整備、ライセンス選定など）は **作らない**。自分の操作環境と快適性に絞る。

---

## 2. プラットフォーム & 技術スタック

- スタック：**Vite + Svelte + TypeScript / Dexie.js (IndexedDB) / TailwindCSS / vite-plugin-pwa**
- 動作形態：**自分の PC でのローカル実行**（`npm run dev` or `vite preview`）と、自分のスマホへの **PWA インストール**。公開ホスティングはしない
- 対応プラットフォーム：自分が使っている PC（Windows）と自分のスマホのみ。他環境は考慮しない
- 不採用：Tauri / Electron（PWA で十分。配布バイナリを用意する動機がない）
- **禁止事項**：サーバー前提機能、外部 API 必須機能、ユーザーデータの外部送信

## 4. 機能要件（チェックリスト）

### 4.1 作品管理（Phase 1）
- [ ] 作品 / 章 / 話 の 3 階層で管理できる
- [ ] 作品・章・話の CRUD（追加 / 改名 / 並び替え / 削除）
- [ ] 削除はゴミ箱経由（即時消去ではなく復元可）
- [ ] 作品ごとに表紙画像・あらすじ・タグを保持できる

### 4.2 エディタ（Phase 1）
- [ ] 保存形式は **青空文庫記法のプレーンテキスト**（`|漢字《かんじ》`、傍点 `《《…》》` 系、改ページ等）
- [ ] 縦書き / 横書きを切り替えられる
- [ ] 選択範囲に対してルビ・傍点を挿入するツールバー
- [ ] エディタ + 装飾プレビューの 2 ペイン表示（プレビューは縦書きでも可）
- [ ] フォント・行間・字間の最低限のカスタム（Phase 2 のテーマと連動）

### 4.3 自動保存・履歴（Phase 1）
- [ ] 入力後 N 秒の debounce で IndexedDB に自動保存（N は設定で変更可）
- [ ] 話単位でスナップショット履歴を直近 X 件保持（容量上限内で循環）
- [ ] 履歴から任意のスナップショットに復元できる

### 4.4 メタデータ（Phase 1）
- [ ] **キャラクター**：名前 / 別名 / 属性（年齢・性別・所属など自由項目）/ 関係性（他キャラへのリンク）
- [ ] **世界観・用語集**：用語名 / 読み / 説明 / カテゴリ
- [ ] **プロット**：作品単位のメモ、話単位のあらすじ・伏線・タイムライン
- [ ] エディタからメタデータ項目を参照（サイドペインまたはホバー）できる

### 4.5 執筆統計・KPI **(Phase 2)**
- [ ] 日次文字数を自動記録
- [ ] 連続執筆日数（streak）を表示
- [ ] 累計文字数・作品別文字数
- [ ] 日次目標値の設定と達成率表示
- [ ] 直近 N 日の簡易グラフ（依存ライブラリは最小限・自前 SVG でも可）

### 4.6 全文検索・置換 **(Phase 2)**
- [ ] 作品横断の全文検索（章・話単位でヒット位置を提示）
- [ ] 正規表現対応の検索
- [ ] 置換は **プレビュー → 確定** の 2 段階（誤爆防止）
- [ ] キャラ名・用語名でのメタデータ検索

### 4.7 エクスポート（Phase 1）
- [ ] **TXT**：青空文庫記法のまま書き出し
- [ ] **なろう貼付用**：なろう／カクヨムにそのまま貼れる整形
- [ ] **EPUB 3**：縦書き・ルビ保持
- [ ] エクスポート対象を 作品全体 / 章 / 話 から選べる

### 4.8 バックアップ／復元 **(Phase 2)**
- [ ] 全 IndexedDB を **zip 一括 export**（JSON + 添付画像）
- [ ] zip からの **import**（既存データに対して 上書き / マージ / 別作品として を選択可）
- [ ] 復元前に整合性チェック・差分プレビュー
- [ ] バックアップ責任はユーザー側にあることを UI で明示

### 4.9 テーマ **(Phase 2)**
- [ ] **ダーク / セピア / ライト** のテーマ切替
- [ ] フォント・行間・字間のカスタム
- [ ] テーマ設定は IndexedDB に永続化、PWA 起動時に即時適用

### 4.10 文字数カウント（Phase 1）
- [ ] リアルタイム文字数表示（章 / 話 / 作品単位）
- [ ] 原稿用紙換算（400 字）の補助表示
- [ ] ルビ・傍点記法を除いた「実文字数」もカウント

## 5. 非機能要件

- [ ] **オフライン完全動作**：PWA、初回ロード後はネット不要
- [ ] **データ局所性**：すべて IndexedDB に保存、外部送信なし
- [ ] **性能**：PWA キャッシュ後の起動 < 1 秒、10 万字オーダーの作品を編集してもタイピング遅延が体感されない
- [ ] **対応ブラウザ**：自分が使っているブラウザのみで動けばよい（PC: Chrome / Edge、スマホ: 自分の端末既定ブラウザ）。それ以外の動作保証はしない
- [ ] **単一ユーザー前提**：同時編集ロック・権限管理・認証は不要
- [ ] **ストレージ上限警告**：IndexedDB の上限近接時に警告し、export を誘導
- [ ] **プライバシー**：解析ツール / 外部フォント CDN / 外部追跡を導入しない（規約整備は不要、自分しか使わないため）

## 6. データモデル概要（Dexie 想定テーブル）

実装詳細は別途設計するが、本書の段階で扱う論理エンティティは以下：

- `works` 作品
- `chapters` 章
- `episodes` 話（本文を保持）
- `characters` キャラクター
- `terms` 用語集
- `plots` プロット
- `snapshots` 自動保存スナップショット
- `settings` UI / 自動保存間隔 / テーマ等
- `stats_daily` 日次統計

ID は ULID 等の文字列、relations は外部キー文字列のみ（クエリは Dexie のインデックス範囲で完結）。

## 7. 受け入れ基準（Phase ごとの DoD）

### Phase 1（MVP）
- [ ] 作品作成 → 章 / 話追加 → 縦書き＋ルビ入力 → 自動保存 → TXT / なろう / EPUB の各エクスポートが一連で動く
- [ ] アプリを閉じて再起動してもデータが失われない
- [ ] PWA としてインストールでき、オフラインで起動できる

### Phase 2
- [ ] 日次 KPI が連続 7 日以上記録され、グラフに反映される
- [ ] 全文検索・置換が作品横断で動き、置換のプレビューと確定が分離している
- [ ] zip バックアップ／復元が往復してもデータ破損 0
- [ ] テーマ切替が永続化され、再起動後も維持される

## 9. 用語集

- **Nola**：本プロジェクトが代替対象とするクラウド小説執筆アプリ
- **青空文庫記法**：`|漢字《かんじ》` 形式のルビ記法など、青空文庫で採用されているプレーンテキスト記法
- **なろう形式**：小説家になろう / カクヨム等にそのまま貼り付け可能なテキスト整形
- **EPUB**：電子書籍の標準フォーマット。本アプリでは EPUB 3（縦書き・ルビ対応）
- **PWA**：Progressive Web App。Service Worker でオフライン動作・ホーム画面追加が可能な Web アプリ

## 10. 画面構成

主要画面の最小セット。実装時はサイドナビ＋メインペインの 2 カラム構成を基本とする。

- [ ] **ホーム / 作品一覧**：作品サムネイル、累計文字数、最終更新日、ピン留め
- [ ] **作品ダッシュボード**：当該作品の章/話一覧、KPI ミニグラフ、ToDo（伏線・宿題メモ）
- [ ] **執筆エディタ**：本文＋プレビュー 2 ペイン、左にメタデータドロワー（キャラ/用語/プロット）
- [ ] **キャラクター管理**：一覧 / 詳細 / 関係グラフ（簡易）
- [ ] **世界観・用語集**：カテゴリ別一覧、検索
- [ ] **プロット**：作品全体メモ、話別あらすじ、タイムライン（Phase 2 で時系列ビュー）
- [ ] **検索**：作品横断・正規表現対応 **(Phase 2)**
- [ ] **統計**：日次/累計/streak、目標達成率 **(Phase 2)**
- [ ] **設定**：自動保存間隔、テーマ、フォント、エクスポート既定、バックアップ操作
- [ ] **ゴミ箱**：削除済み作品/章/話の復元・完全削除

スマホ時は 2 カラムを 1 カラムにフォールバックし、サイドナビはオフキャンバスにする。

## 11. 主要ユーザーシナリオ

各シナリオは Phase 1 の DoD を満たす最低ラインと一致する。

- [ ] **シナリオ A：新規作品を書き始める**
  作品作成 → 章 1・話 1 を自動生成 → エディタが開く → 数文字入力 → debounce 後に自動保存される
- [ ] **シナリオ B：縦書きでルビを振る**
  エディタで文字列を選択 → ツールバーの「ルビ」→ 読みを入力 → `|漢字《かんじ》` が挿入され、プレビューで縦書きルビが正しく表示される
- [ ] **シナリオ C：なろうに投稿する**
  話を選択 → エクスポート → なろう形式 → クリップボード or `.txt` で取得 → なろう投稿フォームに貼って崩れない
- [ ] **シナリオ D：別端末に移す（Phase 2）**
  PC で zip バックアップを取得 → スマホ PWA で zip インポート → 全作品・履歴・設定が再現される
- [ ] **シナリオ E：誤って消した話を復元する**
  ゴミ箱を開く → 該当話を選択 → 「復元」→ 元の章配下に戻る
- [ ] **シナリオ F：執筆習慣を維持する（Phase 2）**
  起動時のホームに streak と日次目標達成率が出る → 目標未達なら強調表示

## 12. キーボード操作・自分用の操作快適性

長時間執筆を前提にするため、マウス無しで主要動作が完結することを重視する。第三者向けの汎用アクセシビリティ準拠（WCAG 等）は**対象外**。自分が長時間使って疲れない範囲を満たす。

- [ ] エディタは IME と衝突しないキー設計（ショートカットは `Ctrl` ベース、`Esc` 単押しの破壊的動作なし）
- [ ] 自動保存・手動保存（`Ctrl+S`）・スナップショット作成（`Ctrl+Shift+S`）
- [ ] ルビ挿入（`Ctrl+R` 等）、傍点トグル（`Ctrl+.`）、太字 / 強調はマークアップに対応する記法のみ
- [ ] 章・話ペイン / メタデータペインの開閉キー
- [ ] フォーカスリングが見える（Tailwind の `focus-visible` 程度で十分）
- [ ] テーマ全種で自分が読みやすいコントラストになっていること（自己評価で OK）
- [ ] 縦書き時のキャレット移動・選択が、自分の使うブラウザで破綻しないこと

## 13. データ可搬性とマイグレーション

ローカル完結ゆえに、アプリ更新でデータが壊れないことが最重要。

- [ ] **スキーマバージョン**を Dexie のバージョン管理機構に乗せ、上方互換マイグレーションを書く
- [ ] バージョンアップ時、起動直後に **自動スナップショット**（壊れた場合の復旧用）
- [ ] **エクスポート JSON にスキーマバージョンを埋め込む**。インポート時にバージョン差分を検出し、必要なら順次マイグレーション
- [ ] 互換性を壊す変更は禁止（必ず変換パスを用意）
- [ ] エクスポート JSON のフォーマットは `docs/` に別途規定（Phase 2 で固める）

---

## 14. 非対象（Out of Scope）

完全に個人専用プロジェクトであるため、以下は **恒久的に対象外**（Phase 3 でも実装しない）。

- **第三者への頒布・公開・サービス化**（リポジトリ公開、デプロイ URL の他人共有、ライセンス整備、利用規約・プライバシーポリシー作成 等）
- マルチユーザー / 共同編集 / コメント機能 / 認証
- 一般ユーザー向けの広範なブラウザ互換、汎用アクセシビリティ準拠（WCAG 等）、多言語対応
- 解析・トラッキング・広告
- AI 自動生成・自動校正（将来検討するとしても本書の対象外）
- ネイティブビルド（Tauri / Electron）。PWA で不足が出たら Phase 3 で再評価
